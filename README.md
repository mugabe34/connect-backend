# Connect Backend

## Run locally

1. Copy `.env.example` to `.env` and set `MONGO_URI` and `JWT_SECRET`.
2. Install dependencies with `npm ci`.
3. Run `npm test` to build and run the tests, then `npm start` to start the API.

## Deploy on Render with MongoDB Atlas

1. Create an Atlas cluster and database user. Add the Render service's outbound IP ranges to the Atlas IP access list.
2. In Render, create a Blueprint from this repository's `render.yaml`.
3. Set `MONGO_URI` to the Atlas connection string and `CLIENT_URLS` to the deployed frontend origin, with no trailing slash. Keep `JWT_SECRET` generated by Render.
4. Deploy and verify `/api/health`.

The service listens on Render's `PORT` and uses `/api/health` as its health check. Never commit `.env` or paste secrets into source control. If a real credential was ever committed, rotate it; deleting the file from the latest commit does not remove it from Git history.

Uploaded product images and avatars are currently stored on the service's local filesystem. Render's default filesystem is ephemeral, so configure durable object storage or a persistent disk before relying on uploaded images in production.
